## 1. Спецификация 18 варианта

**Формула варианта:**  
ИБ | ИЗ2 | ПЗ1 | Д1ОЗ1 | Д1ОО1 | Д2П2 | Д2Б4 | ОР1 | ОД3[cite: 12]

| Код | Параметр | Расшифровка логики функционирования |
| :--- | :--- | :--- |
| **ИБ** | Тип источников | **Бесконечный источник.** Источники генерируют задачи непрерывно на протяжении всего времени работы системы.[cite: 12] |
| **ИЗ2** | Закон генерации | **Равномерный закон распределения** интервалов генерации кадров на отрезке $[a, b]$.[cite: 12] |
| **ПЗ1** | Закон обслуживания | **Экспоненциальный закон распределения** времени нейросетевого инференса с параметром $\mu$.[cite: 12] |
| **Д1ОЗ1** | Дисциплина постановки | **Заполнение буфера «по кольцу».** Поиск свободного слота начинается от текущего указателя буфера $УБ$. При записи слот занимается, а $УБ = (index + 1) \pmod N$.[cite: 12] |
| **Д1ОО1** | Дисциплина отказа | **Отказ под указателем.** Если буфер полон, вытесняется (drop) задача, находящаяся непосредственно в ячейке под $УБ$. Новая задача занимает освобожденный слот, $УБ$ смещается на $+1$.[cite: 12] |
| **Д2П2** | Выбор прибора | **Выбор свободного прибора «по кольцу».** Поиск начинается от текущего указателя приборов $УП$. Задача передается первому свободному NPU, а указатель смещается: $УП = (k + 1) \pmod M$.[cite: 12] |
| **Д2Б4** | Выбор заявки | **Приоритет по номеру источника.** Обслуживается задача источника с наивысшим приоритетом ($И_1 > И_2 > И_3$). При равных приоритетах действует дисциплина **LIFO** (наиболее свежая заявка).[cite: 12] |
| **ОР1** | Отражение результатов | **Сводные таблицы.** Фиксация $P_{отк}$, $T_{преб}$, $T_{ож}$, $T_{обсл}$, $D_{ож}$, $D_{обсл}$ и $K_{исп}$ вычислителей.[cite: 12] |
| **ОД3** | Отражение динамики | **Пошаговый стенд с визуализатором состояний.** Отображение кольцевого/зонного буфера, состояния очереди событий и миграции указателей $УБ$ и $УП$.[cite: 12] |


## 2. Реализованные расширения (Бонусы)

1. **Микросервисная архитектура:**
   * Программный комплекс разделен на 3 изолированных сервиса под управлением Docker Compose с межсервисным REST API и защитным fallback при сбоях сети.
2. **Зонная память (Zoned Buffer):**
   * Реализовано динамическое переключение между общим кольцевым буфером и зонной организацией памяти (квотирование слотов под каждый источник для исключения эффекта монополизации очереди).
3. **Автоматический синтез архитектуры (Этапы 3 и 4):**
   * Параллельный Grid Search перебор сетки конфигураций $(M, N, Mode)$.
   * Автоматическая проверка критериев ТЗ ($P_{отк} \le 10\%$, $K_{исп} \ge 80\%$, $\rho \approx 1$) и подбор оптимума по критерию стоимости.
   * Интерактивные графики зависимостей на Recharts.
4. **Покрытие модульными тестами:**
   * 100% покрытие ключевых алгоритмов вытеснения, приоритетов и указателей через `go test`.

## 4. Быстрый запуск

### Запуск через Docker Compose (Рекомендуемый)

Для сборки образов и старта всех контейнеров выполните в корне проекта:

```bash
docker compose up --build

```

Точки доступа к сервисам:

* **Веб-дашборд:** http://localhost:3000
* **Ядро СМО (REST API):** http://localhost:8080/api
* **Генератор распределений:** http://localhost:8081/api

Для остановки всех контейнеров:

```bash
docker compose down

```

---

### Локальный запуск без контейнеров

1. **Запуск сервиса распределений:**
```bash
cd services/generator-service
go run cmd/main.go

```


2. **Запуск ядра моделирования:**
```bash
cd services/engine-service
go run cmd/server/main.go

```


3. **Запуск фронтенда:**
```bash
cd services/frontend
bun install
bun run dev

```


Интерфейс откроется по адресу: http://localhost:5173


## 5. Запуск модульных тестов

Для проверки алгоритмов кольцевого буфера, дисциплины выбивания Д1ОО1, приоритетов Д2Б4, кольца приборов Д2П2 и зонной памяти выполните:

```bash
cd services/engine-service
go test -v ./internal/engine

```

Тесты проверяют:

* Циклическую запись в кольцевой буфер и корректный сдвиг указателя $УБ$.
* Вытеснение заявки строго из слота под указателем $УБ$ при переполнении буфера.
* Приоритетное извлечение заявок ($И_1 > И_2 > И_3$) и логику LIFO при равенстве приоритетов.
* Циклическое распределение задач по приборам с указателем $УП$.
* Полную изоляцию зон источников в зонном буфере при локальном переполнении.

## 6. Спецификация REST API (`engine-service`)

| Метод | Эндпоинт | Назначение |
| --- | --- | --- |
| `POST` | `/api/init` | Сброс и первичная инициализация модели (поддерживает `{ "buffer_mode": "RING" | "ZONED" }`) |
| `POST` | `/api/step` | Выполнение одного дискретно-событийного такта симуляции по календарю событий |
| `POST` | `/api/auto` | Автоматический прогон с оценкой точности по правилу $10\%$ относительной погрешности |
| `POST` | `/api/experiment` | Параллельный параметрический Grid Search по сетке параметров для этапов 3–4 |
